## 1. Goal

Replace the single-shot Python CLI with a long-running, UI-driven tool for KNX-Entity-Lifecycle-Management in Home Assistant. Cover the migration job, ongoing maintenance, conflict-detection, and backup/restore. Distribute as **HA Add-on** + parallel HACS-Add-on-Listing. Phase later into **Open-Core SaaS** with free Add-on + license-gated server-side premium features.

Primary user: KNX-house-owner running Home Assistant 2026.5+ on HAOS / Supervised / Container.

## 2. Non-Goals

- Standalone PC-Service variant (dropped after pivot to HA-Add-on)
- Browser-only public SaaS without HA Add-on (rejected — File-Picker UX, no FS access)
- TS-Port of core library (Add-on hosts Python — Reuse 1:1)
- ETS-Live-Pull (no public ETS-API exists; only via local KNX/IP-Tunnel — out of scope)
- HA Core (venv) support — CLI remains for that minority

### 3.2 Key Boundaries

- **Browser ↔ Backend:** REST for CRUD, WebSocket for live entity-state stream
- **Backend ↔ HA:** WS for config_store-CRUD via HA-KNX-Commands, REST only for `/api/states/*` reads
- **Core-Library:** pure Python, no I/O, fully testable
- **HA-Client + FS-Adapter:** thin I/O layers, mockable
- **SQLite:** append-only migration audit-log, no destructive operations

### 3.3 Authoritative Source

| Layer | Authority for |
|---|---|
| HA | Entity-State + Config_Store |
| SQLite | Audit-Log + Rollback-Snapshots (append-only) |
| YAML-Files | User-owned (Tool reads+writes, never HA-managed) |
| Browser | Stateless View (IndexedDB only for Token-Cache + UI-Prefs) |

### 3.4 Why HA-Add-on, not HACS-Integration

- Tool **manipulates** entities, doesn't **become** an entity → HACS-Integration's main value (entity/service registration) is unused
- Filesystem-heavy + multi-view SPA fits Docker bind-mount + Ingress naturally
- Supervisor-Token = zero-friction auth
- HACS-Integration would be a misuse of mechanism (would require panel-registration + integration-lifecycle just to host an SPA)
- Add-on can ALSO be listed in HACS (HACS supports add-on discovery)

### 3.5 Free vs Premium Split

**Free (Add-on, MIT, GitHub-public):**
- YAML→UI Convert (all 9 domains)
- Entity-Browser + inline edit
- Dry-Run + GA-Conflict-Checker
- History + Rollback (local in `/data/`)
- UI→YAML Backup
- → ~80–90% of use cases

**Premium (License-JWT-gated, server-required):**
- .knxproj-Import with Smart-ETS↔HA-Entity-Matching (heavy parser + wizard)
- AI-Label-Suggestions (LLM API-cost incurred by license-server)
- Cloud-History-Sync (cross-device, encrypted-at-rest)
- Multi-HA-Profile-Sync (Test↔Prod-Diff)
- Template-Library (curated MDT/Gira/Jung presets with GA-pattern detection)
- Bulk-Operations (find+replace GAs across N entities, mass-rename)
- Team-Sharing (export/import house-structure without raw YAML)

Pricing target: ~7 €/mo or ~60 €/yr. Distribution via **LemonSqueezy** (Merchant-of-Record → EU-VAT handled, no own Impressum-VAT burden).

## 5. Data Flow

### 5.1 YAML → UI Convert (Slices 1–2)

1. User picks YAML file (`/api/yaml/files`).
2. `GET /api/yaml/parse?path=knx/sensor.yaml` → `fs_adapter.read()` → `core.parser.parse()` → `ParsedDomains[]`.
3. Browser shows preview list.
4. User clicks Dry-Run → `POST /api/convert/dry-run` → `core.builders.*` → simulated config_store-diff + `core.conflict.check_gas()`.
5. Browser `DiffView`: green=add, yellow=conflict-warn, red=collision-block.
6. User clicks Commit → `POST /api/convert/commit`:
   - For each entity: `ha_client.ws_send("knx/create_<domain>", {config, name, ...})` — HA-KNX integration writes entity_registry + config_store atomically.
   - If `device_class`: `ha_client.rest_post("/api/config/entity_registry/update", {entity_id, device_class})`.
   - `db.insert_migration_row(...)`.
7. WS push → browser entities-store updates → list refreshes.
8. After all commits: `db.commit_migration_summary(...)`.
9. Success-toast + link to History-View.

**Critical:** Step 6 uses HA-KNX-WS-Commands → HA writes `.storage` itself → **Bugfix #1 (`expose: []`) + #2 (entity_registry-Update) become Non-Issues**. We never write `.storage` directly.

### 5.2 GA-Conflict-Check (Slice 3)

1. `POST /api/conflicts/check {new_yaml_or_parsed}`.
2. Backend:
   a. `core.parser.parse(new)` → `new_gas_set`.
   b. `ha_client.ws_send("config/entity_registry/list", domain=knx)` → existing entities.
   c. Per existing: `ha_client.ws_send("knx/get_entity_config", entity_id)` → config_store entry.
   d. `core.conflict._walk_gas(existing)` → `existing_gas_set` with owners.
   e. Intersect new ∩ existing → `ConflictReport[]`.
3. Browser: `ConflictTable {ga: 5/2/12, conflicts_with: [sensor.alt, switch.test]}`.

### 5.3 UI → YAML Backup (Slice 4)

1. `GET /api/yaml/export?domain=light&format=yaml`.
2. Backend:
   a. `ha_client.ws_send("config/entity_registry/list", domain=light, platform=knx)`.
   b. Per entity: `ha_client.ws_send("knx/get_entity_config", entity_id)` → ui_entry.
   c. `core.reverser.to_yaml(ui_entry)` → yaml-dict.
   d. `yaml.safe_dump({light: [...]}, sort_keys=False, allow_unicode=True)`.
3. Browser: download OR `POST /api/yaml/save?path=knx/light_backup.yaml`.
4. `fs_adapter.write_atomic(path, content)` → tempfile + rename.

### 5.4 History + Rollback (Slice 5)

1. `GET /api/history?limit=50` → `List[Migration]`.
2. Click row → `GET /api/history/{id}` → migration + affected_entities + affected_gas + before_snapshots.
3. `DiffView` renders before/after.
4. Rollback → `POST /api/history/{id}/rollback`. Per affected_entity (reverse order):
   - `created` → `knx/delete_<domain>(unique_id)`.
   - `modified` → `knx/update_<domain>(before_snapshot)`.
   - `deleted` → `knx/create_<domain>(before_snapshot)`.
   - New migration row inserted (`reason="rollback of {id}"`). Rollback is a new migration; nothing is deleted from DB.

### 5.5 Live Entity-Stream (all slices)

1. Browser opens `WS /ws/state-stream`.
2. Backend opens HA-WS, subscribes `state_changed` events.
3. Backend filters domain ∈ {light, switch, cover, binary_sensor, sensor, climate, time, datetime} + platform=knx.
4. Forward as `{entity_id, state, attributes}` to browser WS.
5. Frontend `entities-store.update(payload)` → Svelte $state reactivity → UI re-render.

## 6. Error Handling

| Layer | Failure-Modes | Response |
|---|---|---|
| Core (pure) | YAML-malformed, unknown DPT, setpoint_shift-climate | `ParseError` / `UnsupportedFeature` with entity-name + line. Caller decides. |
| Adapters (I/O) | FS R/W fail, HA-WS-Disconnect, HA-Auth-Error, HA-Timeout | Typed exceptions. Auto-reconnect WS exp-backoff 1s→30s, max-retries=5. |
| Routers (API) | Validation-Error (Pydantic), Permission, License-Check-Fail | Map to HTTP-Status 400/401/402/403/422/503. JSON body `{error: {code, message, hint?, entity?}}`. Log full traceback. |
| WS-Stream | HA disconnects mid-stream | Browser sees disconnect → reconnect-Toast + auto-reconnect with backoff. |
| Frontend | API-Error, Network-Fail, License-Invalid | Error-Boundary per route. Inline `Callout` with action (retry / view-details / downgrade-mode). |

### Critical Error Categories

**Commit-Mid-Failure (Slice 2):** Migration-Row with `status=partial`, per-entry `applied` flag. ResumeButton → `POST /api/migration/{id}/resume`. DB is source-of-truth.

**GA-Conflict at Commit (Slice 3):** Re-check current state before each ws-call. On conflict: skip entity, mark `applied=false, reason="conflict_at_commit"`, continue. User handles via summary.

**WS-API-Surface-Mismatch:** Adapter detects 4xx → `HASchemaError(expected X, got Y, ha-version <ver>)`. Router → 503 with issue-link + supported-version. Mitigation: smoke-tests against real HA in CI.

**YAML File-Lock (Slice 4):** `fs_adapter.write_atomic()` (tempfile + rename). Retry 3× on rename-conflict, then surface "File locked, close editor".

**License-Check-Fail (Phase 6+):** 7-day grace-period via JWT `exp` + local cache. After grace: 402 → `PaywallGate` with renewal-button. Free-features remain functional regardless.

**Rollback-Failure (Slice 5):** Pre-check diff vs before-snapshot → `ConflictReport`. If non-empty: "Partial-Rollback possible" + skip-list. User confirms, skipped entries → manual-handle-notice.

### Logging

- Backend: `logging` (Bugfix #11), JSON-formatted, `LOG_LEVEL` env, default INFO.
- Add-on logs flow into HA-Add-on-Log-Viewer (s6-overlay redirect).
- Frontend: console-errors. **No external telemetry** (privacy).
- DB: no separate log table — migration-rows carry `status` + `error_message`.

### User-Facing UX

Errors always include: **what happened** + **what to do** + **action button** where applicable. Pattern from the HTML example's `.callout`.

## 9. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| HA-KNX-WS-Surface incomplete for some domains | Medium | High | Spike day-1 of Slice 1. Fallback: `.storage` direct-write + HA-reload trigger (re-enables Bugfix #7). |
| HA-KNX changes WS-command schema between versions | Medium | Medium | Version-pin tests in CI matrix. Schema-error → 503 with version-info. |
| Premium features have OSS equivalents (xknxproject, etc.) | High | Medium | Differentiate via UX/Wizard-quality, server-side AI, cross-device sync (no OSS equivalent). |
| KNX-HA-user-base too small for SaaS viability | Medium | High | Free tier always covers 80%+ use cases → tool exists regardless of monetization success. |
| Add-on multi-arch build complexity | Low | Low | Use ghcr.io/home-assistant/<arch>-base-python — multi-arch matrix pre-built. |
| License-bypass via fork (open-source code) | Certain | Low | Premium-features require server-side compute (LLM, sync) — fork can't replicate. |
